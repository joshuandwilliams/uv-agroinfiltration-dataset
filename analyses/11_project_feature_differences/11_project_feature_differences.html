Do the hand-crafted features differ between projects?

Date: 07/08/2026

GOHREP

Goal:

Test whether the twelve hand-crafted image features computed in 10_segmentation_and_feature_extraction differ significantly between the eight source projects that contributed images to the dataset, and quantify how large any differences are.

Hypothesis:

The features will differ between projects. The dataset is pooled from independent experiments run by different people, on different plants, with different cameras, exposures and imaging geometry, so the whole-leaf brightness/colour features (leaf_bright, mean_green, log_gr) should carry a clear project signature. The contrast-type features that compare the CDA against its own leaf (green_gap, ent_gap) are internally normalised by the leaf they came from, so they were expected to be more stable across projects.

Rationale:

Two things ride on this. First, if features carry a project signature, then a model trained on the pooled dataset can partly key on imaging batch rather than on cell death, and any accuracy estimate that does not hold out whole projects is optimistic about generalisation to a new lab or camera. Second, project is confounded with severity in this dataset (projects differ strongly in their score-class mix, 04_project_level_analysis §5), so a raw project difference in a feature could simply reflect that one project’s leaves are more diseased. Every test here is therefore run twice, once raw and once after removing the severity score’s effect, so genuine imaging-batch differences are separated from severity composition.

Two structural facts constrain the analysis. Crops from the same source leaf share lighting, plant and tissue, so crops are not independent, and the independent unit is the source leaf (10_segmentation_and_feature_extraction/10b_score_prediction §2 makes the same argument for cross-validation). And the projects are very unequal in size, from 4 to 89 leaves. The primary test is therefore a leaf-level permutation ANOVA, which needs no distributional assumption and permutes whole leaves, with a mixed model (crops nested in leaves) as a parametric companion.

2.3 Score adjustment

Score adjustment removes each severity class’s mean from a feature, pooled over the whole dataset, and keeps the residual. A project difference that survives this is a difference between projects at matched severity, which is the imaging-batch effect of interest rather than a difference in disease mix.

3. Does each feature differ between projects?

3.1 Leaf-level permutation ANOVA (primary test)

For each feature, the one-way ANOVA F statistic across projects is computed on the leaf means, then the null distribution is built by randomly reassigning the project labels of whole leaves 9,999 times. Permuting leaves rather than crops is what keeps the test honest, since crops within a leaf are correlated. Permutation also avoids assuming normality or equal variances, both of which are doubtful with project sizes from 4 to 89 leaves. Effect size is η², the share of between-leaf variance in the feature attributable to project. The twelve p-values are Benjamini-Hochberg corrected.

Code 
# 3.1.1
f_stat <- function(y, g) {
  g <- factor(g)
  group_mean <- tapply(y, g, mean)
  group_n <- tapply(y, g, length)
  ss_between <- sum(group_n * (group_mean - mean(y))^2)
  ss_within <- sum((y - group_mean[g])^2)
  c(
    F = (ss_between / (nlevels(g) - 1)) / (ss_within / (length(y) - nlevels(g))),
    eta2 = ss_between / (ss_between + ss_within)
  )
}

n_perm <- 9999
perm_test <- function(y, g, seed) {
  set.seed(seed)
  observed <- f_stat(y, g)
  null_f <- replicate(n_perm, f_stat(y, sample(g))["F"])
  # +1 in both numerator and denominator: the observed labelling is itself one
  # of the permutations, so p can never be 0.
  c(observed, p = (1 + sum(null_f >= observed["F"])) / (n_perm + 1))
}

3.2 Mixed-model likelihood-ratio tests (parametric companion)

The same question asked a second way, at crop level, with the leaf as a random intercept so within-leaf correlation is modelled rather than averaged away. Project is tested by a likelihood-ratio test against the same model without project, and the score-adjusted version adds severity class as a fixed effect (value ~ score_f + Project + (1 | leaf) against value ~ score_f + (1 | leaf)). Effect size is the increase in marginal R² when project is added, which is the share of total variance the project term explains. This is a companion rather than the primary test, because the likelihood-ratio chi-square is anticonservative with only eight groups.

Code 
# 3.2.1
# Marginal R^2 (Nakagawa): variance of the fixed-effect predictions over the
# total of fixed, random-intercept, and residual variance.
r2_marginal <- function(model) {
  var_fixed <- var(as.vector(model.matrix(model) %*% lme4::fixef(model)))
  var_random <- sum(as.numeric(lme4::VarCorr(model)))
  var_fixed / (var_fixed + var_random + sigma(model)^2)
}

# ML (not REML) fits, since the likelihood-ratio test compares fixed-effect
# structures.
lrt_project <- function(value, with_score) {
  dat <- data.frame(
    value = value, Project = feat$Project, source = feat$source, score_f = feat$score_f
  )
  form_full <- if (with_score) value ~ score_f + Project + (1 | source) else value ~ Project + (1 | source)
  form_null <- if (with_score) value ~ score_f + (1 | source) else value ~ 1 + (1 | source)
  m_full <- lme4::lmer(form_full, dat, REML = FALSE)
  m_null <- lme4::lmer(form_null, dat, REML = FALSE)
  comparison <- anova(m_null, m_full)
  c(
    chisq = comparison$Chisq[2], df = comparison$Df[2],
    p = comparison$`Pr(>Chisq)`[2],
    dR2 = r2_marginal(m_full) - r2_marginal(m_null)
  )
}

lmm_results <- bind_rows(lapply(seq_along(feat_order), function(i) {

5. Do the twelve features jointly separate projects?

5.1 Multivariate permutation test

The univariate tests ask each feature separately. This asks whether the twelve together separate projects, using a PERMANOVA-style pseudo-F on the standardised score-adjusted leaf means with Euclidean distance, and the same whole-leaf label permutation. R² is the share of total multivariate dispersion between projects.

Code 
# 5.1
Z <- as.matrix(z_leaf[adj_names])
pseudo_f <- function(Z, g) {
  g <- factor(g)
  k <- nlevels(g)
  group_mean <- t(sapply(levels(g), function(l) colMeans(Z[g == l, , drop = FALSE])))
  group_n <- as.numeric(table(g))
  grand <- colMeans(Z)
  ss_between <- sum(group_n * rowSums((group_mean - matrix(grand, k, ncol(Z), byrow = TRUE))^2))
  ss_within <- sum((Z - group_mean[g, , drop = FALSE])^2)
  c(
    F = (ss_between / (k - 1)) / (ss_within / (nrow(Z) - k)),
    R2 = ss_between / (ss_between + ss_within)
  )
}

5.3 Can the project be identified from the features alone?

A practical restatement of the same question. A random forest is trained to predict the project from the twelve crop-level features, under the same source-grouped 5-fold cross-validation used in 10_segmentation_and_feature_extraction/10b_score_prediction §2, so no leaf appears in both the training and held-out folds. Projects are downsampled to equal size, so chance is 1/8 = 12.5% and exact accuracy equals balanced accuracy. A shuffled-label run is included as a leakage check.

Code 
# 5.3
set.seed(42)
min_n <- min(table(feat$Project))
balanced_idx <- unlist(lapply(levels(feat$Project), function(p) {
  idx <- which(feat$Project == p)
  if (length(idx) > min_n) sample(idx, min_n) else idx
}))

X <- as.matrix(bal[, feat_order])
grouped_cv_accuracy <- function(y) {
  pred <- factor(rep(NA, length(y)), levels = levels(y))
  for (k in 1:K) {
    tr <- fold != k
    model <- randomForest::randomForest(x = X[tr, , drop = FALSE], y = y[tr], ntree = 300)
    pred[!tr] <- predict(model, X[!tr, , drop = FALSE])
  }
  list(
    balanced = mean(vapply(levels(y), function(l) mean(pred[y == l] == l), numeric(1))),
    per_class = vapply(levels(y), function(l) mean(pred[y == l] == l), numeric(1))
  )
}

6. Interpretation and Discussion

  • The features differ between projects, and it is not just severity mix. All twelve features differ significantly between projects at matched severity (leaf-level permutation ANOVA, BH-corrected q < 0.05, §3.1), and the crop-level mixed models agree (§3.2). Only cda_bright_sd is non-significant before score adjustment and significant after, which is what a severity-driven confound looks like when it runs against the batch effect. The tests are on leaf means with whole-leaf label permutation, so the result is not an artefact of treating correlated crops as independent observations.
  • The effects are large for the appearance and texture features. At matched severity, project explains 26-35% of the between-leaf variance in within-CDA greenness variation, whole-leaf greenness spread, whole-leaf brightness, whole-leaf mean green level and CDA brightness (§3.1), and the largest project-to-project gaps reach 2.1-2.5 SD of the between-leaf distribution (§4.2). These are the features expected to track camera, exposure and imaging geometry, so a project signature in them is the expected result rather than a surprise. Projects E and H sit at opposite extremes on every brightness feature, differing by ~2 SD in whole-leaf brightness alone.
  • Internal contrast features are not the safe harbour they were expected to be. The hypothesis was that CDA-vs-leaf contrasts would be stable across projects because they are normalised by their own leaf. green_gap and ent_gap still show substantial project effects (η² ≈ 0.26-0.28 adjusted), so normalising a lesion against its own leaf removes some but not all of the batch effect. The two features that come closest to project-invariant are Shannon entropy (η² ≈ 0.08) and greenness bimodality (η² ≈ 0.08 adjusted, down from 0.27 raw, so most of its apparent project difference is severity mix). Notably, bimodality is the feature used for CDA presence detection in 10_segmentation_and_feature_extraction §4, which is reassuring for that particular use.
  • Jointly, the features carry a strong project signature. The multivariate permutation test gives pseudo-F ≈ 8.8 with project accounting for ~23% of the multivariate dispersion between leaves (p < 0.001, §5.1), and a random forest identifies which of eight projects a crop came from ~41% of the time from the twelve features alone, against 12.5% chance and a 12% shuffled-label control (§5.3). For comparison, the same features predict the exact severity score ~62% of the time in 10_segmentation_and_feature_extraction/10b_score_prediction, so they encode a substantial amount about which experiment produced an image alongside what it shows.
  • Consequence for modelling. Because project identity is partly recoverable from the features, a model trained on the pooled dataset can lean on imaging batch, and the source-grouped cross-validation used in 10_segmentation_and_feature_extraction/10b_score_prediction does not protect against this. It holds out leaves, not projects, so every held-out leaf has same-project leaves in training. The ~62% held-out accuracy reported there should therefore be read as within-dataset performance, and a leave-one-project-out evaluation would be the honest estimate of transfer to a new lab or camera. The same caution applies to the deep-learning models trained on this dataset.
  • Caveats. Project is fully confounded with everything that varies between experiments, including camera, exposure, imaging distance, plant batch, growth conditions and infiltration protocol, so these tests establish that the projects differ, not why. Two projects contribute only four source leaves each (§2.1), so their means are imprecise and their contribution to the effect-size estimates is weak. Score adjustment uses a single pooled per-class mean, which removes the average severity effect but not any project-specific difference in how a given score class looks, and that residual is by construction attributed to project.
